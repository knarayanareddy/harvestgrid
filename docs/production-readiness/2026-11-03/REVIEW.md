# HarvestGrid — source review

## Scope and verdict

**Prototype, not an operational harvest service.** Reviewed public repository `knarayanareddy/harvestgrid` at `5a193ff7776775cc35c29268348df0185b7cbe42`. The frontend has distinct fixture, interactive demo and attempted live modes; the separately started API is fixture-wired. The README explicitly says “Visual estimates cannot establish internal ripeness or food safety” ([README:3–7](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/README.md#L3-L7)). This is a partial static review, not a safety, privacy or production certification. Runtime, installs, builds and tests were **NOT RUN**.

## Architecture and product boundary

[`main.tsx:13–29`](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/apps/web/src/main.tsx#L13-L29) chooses the interactive in-browser demo, fixture client or HTTP client. Separately, [`__main__.py:22–30,52–57`](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/services/api/harvestgrid_api/__main__.py#L22-L57) refuses non-fixture container mode and starts `create_app()`, which defaults to a fixture container and mounts forecasting and notification routers ([app.py:34–48,94–96](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/services/api/harvestgrid_api/app.py#L34-L96)). Ring webhook HTTP tests exercise a separate adapter, not proof of an integrated provider. PostGIS, Redis, Ring, weather, SMS, model artifacts and identity are separate dependencies; their presence in a topology is not proof of live operation.

## Findings ledger

- **HG-1 — High, confirmed static; high confidence.** The API starts `build_fixture_container()`, which instantiates `InMemorySchedulerStore`, an in-memory job registry and idempotency store, synthetic weather and a recording SMS transport ([container.py:256–293](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/services/api/harvestgrid_api/container.py#L256-L293)). Compose states “the API does **not** open either connection” and warns multiple workers fork state ([docker-compose.yml:9–19](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/docker-compose.yml#L9-L19)). Real coordination cannot rely on restart durability or cross-worker consistency. Replace fixture stores and verify the live call path before scaling.
- **HG-2 — High, confirmed static limitation; high confidence.** The shipped entrypoint rejects `mode not in {"fixture", "demo"}`; `demo` is an accepted alias for the same fixture-backed API, not live mode ([`__main__.py:22–30`](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/services/api/harvestgrid_api/__main__.py#L22-L30)). The default container uses fixture tokens, and the README describes synthetic webhook, transport and privacy lifecycle ([README:94–96](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/README.md#L94-L96)). Fixture results do not demonstrate provider access, genuine consent or actual media deletion. Require a separately approved integration and privacy lifecycle.
- **HG-3 — Medium, confirmed static deployment risk; high confidence.** Local compose uses a “local_only” default database password and publishes database and Redis ports ([docker-compose.yml:24–33,44–49](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/docker-compose.yml#L24-L49)). This is not evidence that production credentials leaked; the risk is reusing a local topology on an exposed host. Separate production configuration, require secrets and restrict network access.
- **HG-4 — Medium, unverified provider/replay risk; medium confidence.** The webhook test supplies synthetic `X-Ring-Signature` and `X-Ring-Timestamp` and asserts forged requests fail ([test_ring_webhook_server.py:58–92](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/tests/unit/test_ring_webhook_server.py#L58-L92)); its fixture uses in-memory store and queue ([lines 118–123](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/tests/unit/test_ring_webhook_server.py#L118-L123)). This does not establish the real vendor protocol or replay protection after restart. Validate documentation and sandbox behavior before enabling ingestion.
- **HG-5 — Medium, confirmed static configuration mismatch; high confidence.** The web Dockerfile says `VITE_DEMO_MODE=false` selects “the live-API variant” ([Dockerfile:21–27](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/apps/web/Dockerfile#L21-L27)), but the entry selects HTTP **only** for the literal `live`; `false` selects `FixtureCoordinatorApi` ([main.tsx:19–29](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/apps/web/src/main.tsx#L19-L29)). An operator following that instruction receives fixtures, not live traffic. Align and test the mode contract; reject unsupported values.
- **HG-6 — Medium, confirmed static; high confidence.** The dashboard submits fixed `2026-10-30` reveal start and end times for every approval ([App.tsx:117–129](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/apps/web/src/App.tsx#L117-L129)). An attempted live assignment would carry an unrelated or expired access window. Derive and validate it from the actual approved event, with timezone and expiry tests.
- **HG-7 — High, confirmed static integration gap; high confidence.** HTTP mode asks for `/v1/coordination/board` and assignment/receipt routes and its request helper supplies no bearer header ([httpClient.ts:30–39,63–100](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/apps/web/src/api/httpClient.ts#L30-L100)); the sampled API factory mounts forecasting and notification routers ([app.py:94–96](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/services/api/harvestgrid_api/app.py#L94-L96)). Its actor dependency resolves a bearer token ([deps.py:44–55](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/services/api/harvestgrid_api/deps.py#L44-L55)). No working dashboard-to-API contract is demonstrated; verify routes and authenticated requests end-to-end rather than assuming client session fields authorize them. Other uninspected deployments or middleware may differ.

## Five-discipline assessment

- **Correctness/code:** HG-5–7 are concrete cross-file contract and time-boundary defects; forecast accuracy, assignment outcomes and food safety remain unmeasured. The [README:41–43](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/README.md#L41-L43) labels the interactive path as in-browser fixtures.
- **Automation/testing:** The [web workflow:50–66](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/.github/workflows/pages.yml#L50-L66) freezes the lockfile, typechecks, tests and builds the demo. [Historical Pages run 40122003094](https://github.com/knarayanareddy/harvestgrid/actions/runs/40122003094) succeeded at this same SHA; it is not our run or proof of API/provider behavior. The sampled UI tests use the fixture API and test error/receipt states ([app.test.tsx:60–70,118–135,171–185](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/apps/web/tests/app.test.tsx#L60-L185)).
- **DevOps/operations:** A one-worker, non-root API image and frozen Python environment are intentional ([services/api/Dockerfile:25–37,49–51](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/services/api/Dockerfile#L25-L51)). Health does not establish durability, recovery or notification delivery; infrastructure and restore remain unverified.
- **OWASP/security:** Bearer parsing and role dependencies exist ([deps.py:44–72](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/services/api/harvestgrid_api/deps.py#L44-L72)), while identity is fixture-only. Cross-organization enforcement on every route, injection resistance, secrets rotation, dependency vulnerabilities, residential data retention and deletion through backups are unverified—not findings of proven absence. Python and web lockfiles are inventoried, not audited; action and image tags are not immutable digests.
- **UI/UX/accessibility:** The console provides a skip link, fixture notice and tab semantics with roving keyboard focus ([App.tsx:67–85,166–182,202–219](https://github.com/knarayanareddy/harvestgrid/blob/5a193ff7776775cc35c29268348df0185b7cbe42/apps/web/src/App.tsx#L67-L219)); a test checks `aria-invalid`. Screen-reader behavior, accessible map alternatives, clear consent and real coordinator workflows were not observed.

## Blockers, owner questions and evidence limits

Owner must decide pilot scope, identity provider, authorized Ring capabilities, consent and retention, model/dataset licensing and domain authority, SMS account, hosting and recovery ownership. No credentials, residential media or participant accounts were accessed. Food-safety decisions require qualified human review, not the model's visual estimate.
